# Intent: slice-1-doc-to-graph（文档→图 + 可检索，含 trace 暴露口）

> 本切片是总体意图 Goal 1 + Goal 4（机制部分）的第一次落地。
> 范围：**单篇文档**。跨文档增量合并 / 去重对齐属 S2，本切片明确不做。

## Goal

让用户把一篇文档丢进来，就能自动得到一张"谁和谁、什么关系"的图；问问题时，系统不仅给出答案，还输出一份结构化的记录，说明它是翻过图上哪些实体、哪些关系才得到这个答案。

三个验收点：

1. 单篇文档 → 图（抽出实体 + 关系）；
2. 基于图回答检索问题，答案能追溯到具体实体；
3. 每次检索输出结构化 trace（命中的实体/关系 + 评分），本切片只输出 JSON、不做可视化（可视化属 S3）。

## Constraints

1. **复用 LightRAG**：进程内 `import lightrag`，不自己重写实体抽取、关系抽取、实体对齐。
2. **检索必须输出结构化 trace**（dual-level 检索命中的实体/关系 + 评分）——全项目焊死的硬约束，S3 只在其上做渲染。
3. **纯 Python 后端 + CLI + pytest**：本切片不引入前端、不引入 HTTP 服务（HTTP 到 S4 需要前端时再加）。
4. **单篇文档范围**：不做跨文档增量合并与实体去重对齐（S2 的事）。
5. **规则预算 ≤ 1**：本切片不新增"规则族"，沿用 LightRAG 已有机制。

## Failure Conditions

1. 检索返回了答案，但 trace 为空 / 不含任何实体或关系命中 → 透明窗没焊进去。
2. 喂进一篇可抽取的文档后，图里实体数为 0 或关系数为 0 → 构图失败。
