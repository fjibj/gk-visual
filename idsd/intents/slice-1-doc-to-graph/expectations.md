# Expectations: slice-1-doc-to-graph

> 用户语言，定义"什么算完成 / 什么算失败 / 边界怎么处理"。
> 可执行的具体场景（含断言）在 `holdout/scenarios/slice-1-doc-to-graph/`，构建时代理不可见。

## Success Scenarios

| 场景 | 期望行为 |
|------|----------|
| 喂一篇含多个实体和关系的文档 | 系统建成一张图，能抽出这些实体和它们之间的关系（实体数 > 0 且关系数 > 0） |
| 向图提一个能被图中实体回答的问题 | 返回答案，且答案能追溯到图中的具体实体（不是凭空编造） |
| 提问后检查检索过程 | 返回结果里包含结构化 trace，列出了本次检索命中的实体和关系，且这些实体/关系确实在图里存在 |

## Failure Scenarios

| 场景 | 期望行为 |
|------|----------|
| 检索成功但 trace 缺失或为空 | 系统必须显式失败/报错，绝不悄悄返回一个"看不见过程"的黑盒答案 |
| 喂一篇抽取不出任何实体的文档 | 系统得体处理（不崩溃），明确报告"未抽取到实体"，而不是假装有图 |

## Boundary Scenarios

| 场景 | 期望行为 |
|------|----------|
| 提问一个图中完全不存在的实体 | trace 如实显示"未命中"，系统返回"未找到相关实体"，不编造 |
| 同一实体在一篇文档里被反复提及 | 不因反复提及而出现大量重复节点（单文档内基本一致性；跨文档去重对齐是 S2 的事） |
