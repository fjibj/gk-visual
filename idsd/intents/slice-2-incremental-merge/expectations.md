# Expectations: slice-2-incremental-merge

> 用户语言，定义"什么算完成 / 什么算失败 / 边界怎么处理"。
> 可执行的具体场景（含断言）在 `holdout/scenarios/slice-2-incremental-merge/`，构建时代理不可见。

## Success Scenarios

| 场景 | 期望行为 |
|------|----------|
| 已有含"张三/北京/字节跳动"的图，再摄入一篇含"李四/字节跳动"的文档 | 图累积：实体数 = 两篇并集（张三、李四、北京、字节跳动…都在），第一篇实体不消失 |
| 两篇文档都提到"字节跳动"（同名） | 图中"字节跳动"只出现**一个**节点，描述/关系合并而非出现两个同名节点 |
| 把变体实体（如"字节跳动" 与 "ByteDance"）显式合并到"字节跳动" | 返回结构化结果：删除的源、转移的关系数；合并后图中无"ByteDance"，检索"字节跳动"命中且关系完整 |

## Failure Scenarios

| 场景 | 期望行为 |
|------|----------|
| 摄入第二篇文档后，第一篇的实体消失或图被重建 | 系统必须显式失败/报告，绝不静默丢失已入库的知识 |
| 同名实体在图中出现多个节点 | 系统必须显式失败/报告，绝不假装"对齐了"却实际拆开 |
| 显式合并后源实体未删除、或关系丢失 | 系统必须显式失败/报告，绝不静默产生"半合并"状态 |

## Boundary Scenarios

| 场景 | 期望行为 |
|------|----------|
| 两篇文档**无**重叠实体（完全不相干） | 正常增量，实体数 = 两篇之和，无合并发生，无报错 |
| 显式合并一个**不存在**的实体名 | 得体报错（明确指出哪个实体不存在），不崩溃、不改动图 |
| 变体实体**不**显式合并（用户不干预） | 保持原样：同名才自动合并，变体不自动猜合并（不做危险自动对齐），由人决定 |
