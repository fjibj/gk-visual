# Expectations: slice-6-document-lifecycle

> 用户语言，定义「什么算完成 / 什么算失败 / 边界怎么处理」。
> 可执行的具体场景（含断言）在 `holdout/scenarios/slice-6-document-lifecycle/`，构建时代理不可见。

## Success Scenarios

| 场景 | 期望行为 |
|------|----------|
| 浏览器上传一篇含新实体的文档 | 图长出：实体/关系增加，页面能看见新节点，返回该文档贡献的实体/关系数 |
| 列出文档列表 | 返回库中文档清单，每个文档带 doc_id、贡献的实体/关系数 |
| 删除一篇文档 | 返回结构化结果：只属该文档的实体/关系被清掉，图正确收敛 |
| 重传同一文档（内容修订） | 覆盖更新：旧版独有实体/关系消失，图反映新版；文档列表仍是一篇（非两篇） |

## Failure Scenarios

| 场景 | 期望行为 |
|------|----------|
| 上传文档后图没变化 | 系统必须显式失败/报告，绝不静默「假装上传成功」 |
| 删除文档后孤儿实体/关系残留 | 系统必须显式失败/报告，绝不静默残留 |
| 删除文档后被共享实体误删 | 系统必须显式失败/报告，绝不静默过度删除 |
| 覆盖更新后旧版独有实体/关系残留 | 系统必须显式失败/报告，绝不静默「更新了却新旧并存」 |

## Boundary Scenarios

| 场景 | 期望行为 |
|------|----------|
| 上传一篇无实体的文档（空/纯格式） | 得体处理（提示「无可抽取内容」），不崩溃 |
| 删除一个不存在的 doc_id | 得体报错（明确指出不存在），不改动图 |
| 删除被多文档共享实体的文档（实体仍被其余文档支撑） | 实体保留，只收敛掉该文档独有的证据/关系，不整个删节点 |
| 重传两个不同文档（不同身份） | 并存：各自独立，互不覆盖 |
| 重传与已有文档完全相同的内容 | 幂等/去重：不重复摄入，不产生重复节点（LightRAG duplicate 检测） |
