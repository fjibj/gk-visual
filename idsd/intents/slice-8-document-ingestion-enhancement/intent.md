# Intent: slice-8-document-ingestion-enhancement（文档摄取增强）

> 本切片把「文档摄取」从「粘贴纯文本」扩展到「真实文件 + URL 链接」。
> 复用 S6 文档生命周期管线：格式适配层只做「字节/URL → 纯文本」，下游 `ingest_document` 与文档生命周期零改动。
> 硬依赖：S6（文档生命周期）；顺序上排在 S7 之后。

## Goal

让用户把真实文件（docx/xlsx/pptx/pdf/txt/md）丢进知识库，也能粘贴 URL 链接，系统解析/抓取成纯文本后走 S6 已有的「上传→图」管线长出图。

三个验收点：

1. **文件 → 图**：上传 docx / pdf / xlsx / pptx 等 → 解析成纯文本 → 复用 S1 ingest → 图长出（实体/关系增加，可即时看到）；
2. **解析失败得体**：损坏文件 / 不支持格式 → 明确报错，不静默、不产生垃圾实体、不污染图；
3. **（后置）URL → 图**：粘贴 http(s) URL → 抓取正文 → 转纯文本 → 复用 ingest → 图长出；抓取失败 / 非法目标得体报错。

## Constraints

1. **复用 S6 管线**：适配层只做「字节 / URL → 纯文本」，下游 `ingest_document`、`POST /api/documents`、文档生命周期零改动。
2. **解析用成熟库**：docx→`python-docx`、xlsx→`openpyxl`、pptx→`python-pptx`、pdf→`pypdf`（或 `markitdown` 统一），不自己写格式解析器。
3. **安全（URL 抓取）**：防 SSRF（禁内网 / 环回 / 本地 / 链路本地地址）、超时、响应大小上限、仅 http/https。
4. **规则预算 ≤ 1**：不新增规则族——每个格式一个适配器，URL 一条抓取+正文抽取链。
5. **覆盖更新延续 S6**：同标题文件重传 = 覆盖更新（复用 S6 的 doc_id 身份：标题 slug）。

## Failure Conditions

1. 文件解析后文本为空 / 乱码仍入库 → 污染图。
2. 解析失败静默吞掉（用户以为入库了，其实没有）→ 失败不可见。
3. URL 抓取触发 SSRF（抓到内网 / 本地地址）→ 安全漏洞。
4. 超大文件 / 超大页面无限制拖垮服务 → 稳定性。
5. 不支持的格式 / 协议未明确提示 → 用户体验。

## 优先级（用户 2026-08-17 拍板）

- **文件格式解析 = 本片主体，先做**（更安全、更常用）。
- **URL 抓取 = 后置子项**（安全面更大），待文件格式跑通后再定「同片做完」还是「另立切片」。
