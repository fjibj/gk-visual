# Expectations: slice-8-document-ingestion-enhancement（文档摄取增强）

> 本文定义 S8「文件格式解析 + URL 抓取」的成功 / 失败 / 边界场景，作为 Holdout 判卷依据。
> 注意：URL 抓取为后置子项，开工前可再细化。

## 成功场景（Success）

1. **docx → 图**：上传一个含人/组织的 .docx，解析出纯文本，图里长出对应实体/关系，文档列表出现该文档（标题正确、含实体数）。
2. **pdf → 图**：上传一个文本型 .pdf，解析出可读文本，图长出，无乱码。
3. **xlsx → 图**：上传一个表格 .xlsx，解析出单元格文本，图长出（表格内容被保留为文本）。
4. **覆盖更新**：同标题的 .docx 重传 → 复用 S6 覆盖更新，旧版收敛、图反映新版。
5. **（后置）URL → 图**：粘贴一个 http(s) 网页 URL，抓取正文（去导航/广告），图长出；标题用页面 title 或用户给的名字。

## 失败场景（Failure）

1. **损坏文件**：上传一个损坏的 .docx/.pdf → 解析报错，接口返回明确错误，不产生任何实体/文档记录。
2. **不支持格式**：上传 .exe / 无扩展名 → 明确提示"不支持的格式"，不静默入库。
3. **空内容文件**：上传内容为空的 .docx → 明确报错，不入库。
4. **（后置）SSRF 拦截**：URL 指向 `127.0.0.1` / `10.x` / `169.254.x` / `localhost` → 拒绝抓取，明确报错。
5. **（后置）抓取失败**：URL 404 / 超时 / 非 http(s) 协议 → 明确报错，不产生垃圾记录。

## 边界场景（Boundary）

1. **超大文件**：超过大小上限（如 50MB）→ 拒绝并提示，不拖垮服务。
2. **扫描版 pdf（无文本层）**：解析出空文本 → 明确提示"该 PDF 无文本层，需 OCR"（OCR 后置，不强行做）。
3. **多工作表 xlsx**：只取第一个/所有工作表文本并拼接，行为明确、可预期。
4. **（后置）超大网页**：响应超过大小上限 → 截断或拒绝，行为明确。
5. **（后置）非 UTF-8 编码网页**：尽力按 meta 声明解码，失败则明确报错而非输出乱码。

## 非目标（本片不做）

- 图片内容识别（OCR / 图表理解）——后置，扫描版 PDF 明确提示需 OCR。
- 结构化表格关系抽取（xlsx 表格 → 结构化属性/关系）——属性保持现状（用户 2026-08-17 拍板），表格仅转文本进 description。
- URL 的登录态 / 反爬绕过 / 动态渲染（JS）网页。
