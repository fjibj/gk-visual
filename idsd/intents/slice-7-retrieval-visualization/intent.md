# Intent: slice-7-retrieval-visualization（检索可视化闭环）

> 本切片补上 S3→S4 衔接遗漏的腿：把检索从 CLI 接进浏览器，并在图谱上高亮检索路径、支持多轮颜色演进。
> 前置：S1（trace）、S3（分数）、S4（前端图谱）、S5（编辑回路）。

## Goal

让用户在浏览器里直接检索，并在图谱上看到「走了哪些实体/关系」；多轮对话逐轮叠加，当前轮颜色最深、历史越远越浅。

三个验收点：

1. **前端检索框**：浏览器有检索框，输入问题 → 调后端 `/api/query` → 返回答案 + trace；
2. **图上路径高亮**：trace 命中的实体/关系在图谱上高亮（按分数/命中程度区分），未命中的淡化；
3. **多轮颜色演进**：连续多轮检索，图上叠加多轮路径，当前轮最深、历史逐轮变浅。

## Constraints

1. **复用现有检索**：后端 `/api/query` 直接复用 `graphkb/query.py::query`（答案 + trace），不重写检索。
2. **渲染是展示层**：图上高亮只是给 trace 的命中实体/关系加视觉标记，不改图数据、不新增规则族。
3. **前端 + 后端**：复用 S4 前端，加检索框 + 高亮 + 多轮演进；后端加一个只读查询端点。

## Failure Conditions

1. 检索框输入后，图上有命中却不显示高亮 → 路径可视化没装上。
2. 多轮检索后，历史轮和当前轮颜色无区分 → 演进没体现。
3. 检索结果（trace）与图上高亮不一致 → 可视化骗人。
