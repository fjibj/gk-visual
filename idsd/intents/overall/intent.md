# 意图（Intent）

做一个**能看见检索过程、可手工编辑图谱**的个人知识库。

出发点：现有知识库（如腾讯 IMA）是"上传即用"的黑盒 RAG——文档切块、向量化、相似度检索，全程不可见、不可改。本项目的核心诉求是**透明**：

1. 文档如何变成图（实体、关系）——可见
2. 新文档如何并入既有图（增量、对齐）——可见
3. 检索时走了哪条路径（哪些实体、哪些关系、为什么）——可见
4. 人可以改图，检索尊重人的编辑——可编辑

同时，本项目是 IDSD 方法论「从头做一个完整项目」的第一次完整验证。

## 目标（Goal）

1. **文档 → 图**：LLM 从文档抽取实体（节点）+ 关系（边），构成知识图谱。
2. **增量合并**：新文档并入既有图时不重建整库，且正确对齐同一实体（去重合并）。
3. **图谱可视化 + 手工编辑**：能看整张图，能手改节点/边。
4. **检索路径可视化**：检索时动态展示走了哪些实体/关系；随多轮对话演进，当前步颜色最深、历史越远越浅。
5. **编辑回路**：手工编辑后的图，检索结果随之变化。

## 约束（Constraints）

1. **图引擎复用 LightRAG**（增量更新 + 去重合并是现成能力），不重新发明实体抽取与对齐。
2. **检索路径可视化 = 给检索器加「透明窗」**，不是发明新检索算法；把 LightRAG 的 dual-level 检索中间步骤暴露出来即可。
3. **定位是两条腿**：检索走图（RAG 路线）+ 写时手工编辑（Wiki 路线），二者都要，但以图检索为主干。
4. **全局结构用轻量社区检测**（如 Leiden），不引入 GraphRAG 的重架构（社区摘要 map-reduce）。
5. **最小可行起步**：先地基（构图 + 增量 + 检索），后天花板（可视化 + 编辑回路）；每步可独立验证。
6. **规则预算 ≤ 1**（核心原则）：任何新增机制必须能用「是否新增了规则族」来审视，新增规则须经人工决策。

## 失败条件（Failure Conditions）

1. 新文档加入需要重建整库 → 增量合并没做成。
2. 检索路径仍是黑盒，看不到「凭什么走这条路径」 → 透明窗没装上。
3. 手工编辑图后，检索结果不随之变化 → 编辑回路没闭环。
4. 同一实体被拆成多个节点、或不同实体被错误合并 → 实体对齐失败。
5. 为可视化/编辑引入一套与图检索无关的新规则体系 → 违背「规则越少越好」。
