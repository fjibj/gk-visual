# Expectations: slice-5-edit-loop

> 用户语言，定义「什么算完成 / 什么算失败 / 边界怎么处理」。
> 可执行的具体场景（含断言）在 `holdout/scenarios/slice-5-edit-loop/`，构建时代理不可见。

## Success Scenarios

| 场景 | 期望行为 |
|------|----------|
| 编辑某实体的描述（如补充信息） | 再次检索该实体相关问题，trace 中该实体的命中/分数发生变化 |
| 删除某实体 | 检索不再命中该实体；若因此无命中，得体返回「未找到」而非黑盒答案 |
| 合并两个变体实体 | 检索命中合并后实体，不再命中旧名 |
| 新建一个实体/关系 | 检索能命中新增内容并进入 trace |

## Failure Scenarios

| 场景 | 期望行为 |
|------|----------|
| 编辑后检索命中/分数无变化 | 系统必须显式失败/报告，绝不「界面显示已编辑，检索却纹丝不动」 |
| 删除后检索仍命中旧实体 | 系统必须显式失败/报告，绝不残留已删知识 |
| 合并后检索仍命中旧名 | 系统必须显式失败/报告，绝不留半合并 |

## Boundary Scenarios

| 场景 | 期望行为 |
|------|----------|
| 编辑一个与检索问题无关的实体 | 该问题的检索结果不受影响（不误伤无关路径） |
| 编辑后立刻检索（无 re-embed 时） | 若依赖 embedding 而 Ollama 未起，得体报错而非静默返回旧结果（诚实降级） |
| 检索命中由多实体共同支撑的问题，只编辑其一 | 仅该实体的分数/描述变化，其余命中不变 |
| 新建一个孤立实体（无关系）后检索它 | 已知边界：dual-level 检索不召回孤立节点（LightRAG 固有行为），不视为失败 |
