# Intent: slice-5-edit-loop（编辑回路：编辑 → 检索随之变化）

> 本切片是总体意图 Goal 5 的落地，关闭 Failure Condition 3（编辑后检索不变化）。
> 前置：S1（检索 + trace）、S3（透明窗渲染）、S4（手工编辑）。本切片把「编辑」和「检索」两条腿接成闭环。

## Goal

手工编辑图（建/改/删/合并实体与关系）后，检索结果随之变化——且这个变化可被 trace 呈现（编辑前后命中/分数的差异可见）。

四个验收点：

1. **改实体 → 检索变**：编辑某实体的描述/类型后，检索该实体相关问题时，命中/分数发生变化；
2. **删实体 → 检索不命中**：删除某实体后，检索不再命中它（且不返回无据答案）；
3. **合并 → 检索命中新名**：合并实体后，检索命中合并后的实体，不再命中旧名；
4. **建实体/关系 → 检索可命中**：新建的实体（连同关系）能被检索命中并进入 trace（孤立实体不召回是 LightRAG 固有边界，见 context bundle）。

## Constraints

1. **复用 LightRAG**：编辑复用 S4 已封装的编辑 API，检索复用 S1/S3 的 `query` + trace，不重写检索算法、不重写编辑逻辑。
2. **变化可见**：编辑对检索的影响通过 trace 呈现（编辑前后命中集/分数对比），延续透明窗，不做黑盒「编辑已生效」。
3. **规则预算 ≤ 1**：不新增规则族——编辑回路是「编辑→向量库/图→检索」的既有链路，本切片只验证闭环、补断点。
4. **纯后端 + pytest + holdout**：编辑回路是数据层行为，用 pytest/holdout 判卷（不依赖前端），前端可视化不属本切片。

## Failure Conditions

1. 编辑实体后，检索命中集/分数无任何变化 → 回路没闭环。
2. 删除实体后，检索仍命中该实体 → 删除没传导到检索。
3. 合并实体后，检索仍命中旧名 → 合并没传导到检索。
4. 新建实体后，检索无法命中它 → 新建没传导到检索。
